```
侧栏导航：[MCP 服务] [教案中心] [教材库] …
                          └─ #view-design 一整页
                             ├─ ① 模板工作台：导入 .docx / 全量编辑 / 保存 / 删除 / 按模板导出

```
                    会话页（#view-chat）—— 唯一工作台
   ┌──────────────────────────────────────┬───────────────────────────┐
   │ 消息流（面板打开时右侧自动让位）        │ #docPanel 右侧预览面板     │

**两条链路**（本改造的核心约束）：

| | 会话内内存预览 | WPS 落盘导出 |
|---|---|---|
| 接口 | `POST /api/session/doc-preview` | `POST /api/wps/export` + `GET /api/wps/download` |
| 磁盘 | 不写任何文件 | 写 `content/plans/` 或自选目录 |
| WPS | 不调用、**不查开关** | 依赖 `wps-office` MCP，关掉即拒 |
| 开关 | `skill: doc-session-preview`（只管面板渲不渲染） | `mcp: wps-office` |

## 4. 详细设计

### 4.1 后端（+77 / −1，纯增量）

**① 新 skill：`doc-session-preview`**（`capabilities.py`，+13 行）

```python
SkillSpec(id="doc-session-preview", name="会话文档预览", icon="D",
          desc="AI 生成文档后，在会话页右侧唤起多格式预览面板（内存渲染，不落盘、不调用 WPS）",
          category="文档", builtin=True)
```

- `SkillSpec` 新增 `builtin` 字段：内置能力（无 `skills/<id>/SKILL.md` 实体），
  UI 显示「内置」而不是「文件缺失」；
- 不绑 MCP → 不会因为关 WPS 而显示「依赖已关」；
- 新增 `capabilities.session_preview_ready()`；
- `snapshot()` 新增顶层字段 `session_doc_preview_ready` 与每条 skill 的 `builtin`。

**② 新接口 `POST /api/session/doc-preview`**（`web_server.py`，+77）

```jsonc
// 请求：markdown 留空时会话里最近一份教案兜底
{"payload": {...}, "markdown": "文本", "session_id": "…"}
// 响应（输入原样回传 + 派生预览模型）
{"ok": true, "enabled": true, "title": "3.3 幂函数",
 "markdown": "…", "payload": {...},
 "blocks": [{"title":"教学目标","level":2,"chars":43}],
 "slides": [{"name":"情境导入","minutes":"5","bullets":["…"]}],
 "stats": {"chars":222,"blocks":9,"slides":3,"minutes":20},
 "note": "内存预览：不落盘、不调用 WPS；需要落盘请走 /api/wps/export"}
```

- **无磁盘 IO**：只用 `wps_export.slides_from_markdown()`（纯计算）与 `_plan_blocks()`（纯文本处理）；
- **不查 WPS 开关**，也**不在接口层加闸门**——接口是纯函数，开关只影响前端渲不渲染（响应里的 `enabled`）。

**③ `GET /api/mcp/status`** 增 `session_doc_preview_ready`（1 行）。

**④ 明确未改**：`wps_export.py` 一行未改；`/api/wps/export`、`/api/wps/download` 行为不变；
`mcp_tools.py`、`deploy/*`、wps-skills 安装脚本、`.gitignore` 护栏全部原样。

### 4.2 前端预览面板

**结构**（挂在 `#view-chat` 内，随视图显隐）

```
#docPanel（position:fixed; right:14px; top:74px; bottom:14px; width:var(--docp-w,460px)）
├─ #docPanelGrip        ← 左边缘拖拽条（双击复位 460）
├─ .dp-hd  标题 + 字数·页数 + [导入] [下载 ▾] [位置] [×]
│          └─ 悬停「下载」弹出下载方式菜单：Word(.docx) / PPT(.pptx) / HTML
├─ .dp-tabs 文档 | Markdown | 幻灯片 | 结构
├─ #docPanelBody
└─ #docPanelRes         ← 下载结果条（文件名 + 目录 + 下载到本机）
```

**行为**

| 项 | 设计 |
|---|---|
| 自动唤起 | `handleEv` 的 `done` 分支：`ev.mode==='B'` 或正文含 `Agent B` → `docpFromAnswer(raw, ev.html)` |
| 开关闸门 | `docpFromAnswer` 先确保能力清单到手（`capLoad()`），再按 `session_doc_preview_ready` 决定；服务端返回 `enabled:false` 时也不渲染 |
| 拖拽 | `mousedown` 抓 `#docPanelGrip` → `mousemove` 改 `--docp-w`，夹在 320 ~ min(920,74vw)，存 `localStorage: edu_docpanel_w`，双击复位 |
| 让位 | 打开时给 `#view-chat` 加 `.dp-open`，消息区右内边距 = `--docp-w + 34px` |
| 四页签 | 文档=`mdLight()` 渲染；Markdown=原文 `<pre>`；幻灯片=逐页卡片 +「在新窗口看 16:9」；结构=板块清单+字数 |
| 导出 | 复用既有 `expViaServer()`（前端共用导出层）与 `/api/wps/export`；结果条与「下载到本机」沿用 |
| **下载出口合并** | 原 `[Word][PPT][HTML]` 三个按钮合并为一个 **`下载 ▾`**：鼠标**悬停即弹出**下载方式菜单（Word/PPT/HTML），点击也能开（兼容触屏），选完自动收起 |
| 前置校验 | WPS 未就绪时，菜单里 Word/PPT 两项**灰显但仍可点**（点了在结果条说明原因）；HTML 项不受影响。`capSyncDesignBtn()` 负责刷新这个状态 |

### 4.3 教案中心页面下线

| 原页面部件 | 处置 | 理由 |
|---|---|---|
| 导航项 `design` | **删除** | 不再跳转（要求 1） |
| `#view-design` 整页 | **删除** | 同上 |
| ② DZ 编排台工具栏 + ③ 两栏编辑器 | **删除** | 它的活（编排教案×PPT）由 AI 生成 + 右侧预览面板接管；模型是另一套（`DZ.steps`），与会话教案不互通 |
| 对话内联「导出条」 | **删除** | 面板已承担同样的导出/预览，避免两处入口 |
| **① 模板工作台** | **整体移除**（编辑/保存/删除/格式工具栏/新建空白全删） | 见 §5 决策 1（改为：不要模板） |
| **导入 .docx** | **保留** → 移到面板标题栏「导入」，解析后只进预览 | 用户明确要求「保留导入」 |
| 导出位置选择 / 结果条 | 并入面板（`位置` 按钮 + 结果条），共用 `localStorage: edu_dz_outdir` | 保持一处记忆 |
| `switchView('design')` 调用点 | 改为 `tplDrawerOpen()` | 计划选项卡的「去教案中心编辑」→「打开教案模板」 |
| `views` / `crumbText` / `dz-*` CSS | 清理 | 无残留死引用 |

**顺带修的一个真 bug**：`dzBind` IIFE 开头是 `if(!box) return;`，而 `#dzSteps` 已被删除——
若不处理，`tplBind()` / `planOptsInit()` / `tplRestore()` 会被一起跳过，**模板工作台直接失效**。
已把启动初始化拆成独立的 `appInit()`。

## 5. 关键取舍（需要你确认的就是这几条）

| # | 取舍 | 选择 | 理由 |
|---|---|---|---|
| 1 | **模板工作台要不要一起删？** | **删除**；**只保留导入** | 用户拍板「不要模板，保留导入」。导入改为「把 .docx 拉进预览看+下载」，不再进模板库。代价照实说：①生成的模板无法在界面里编辑/删除，content/templates/ 要手工清理 |
| 2 | 预览要不要也受 WPS 开关控制？ | **不受**，只受自己的 skill 开关 | 要求 4 的「严格区分」；且关掉 WPS 只是想停落盘，不该连带看不了稿 |
| 3 | 预览接口要不要加服务端闸门？ | **不加** | 它是纯函数、无副作用；关掉开关只影响前端渲染。加了反而让「关预览」有可能影响别的调用 |
| 4 | 「可拖拽」怎么理解？ | **拖左边缘调宽**（+ 双击复位、宽度记忆） | 侧边面板的通行做法；比「整体拖动漂浮窗」更稳、不遮内容 |
| 5 | 对话内联导出条留不留？ | **删掉** | 与面板重复；要求 1 明确要下线旧 UI |
| 6 | 编排台删除后 `payload` 接口还要不要？ | **保留**（接口向后兼容） | 要求 3「导出接口行为不变」；且 `payload` 仍能被外部/脚本使用 |
| 7 | 预览的 PPT 解析放哪？ | **复用三期就绪的 `slides_from_markdown()`** | 预览与实际生成的 PPT 用**同一个解析**，所见即所得 |
| 8 | 三个下载按钮怎么收？ | **合并成一个 `下载 ▾` + 悬停菜单** | 面板宽度有限（可拖到 320px），三个按钮会挤；合并后标题栏只剩 `模板/下载/位置/×` |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 删编排台误伤他人功能 | 别人还在用 | 后端接口全保留；只删前端页面与模型；`payload` 路径不变 |
| 模板工作台搬家后事件绑定失效 | 模板功能全挂 | 所有 JS 用 `getElementById` + DOM 常驻（抽屉只是 `display` 切换），绑定点未变；且拆分了 `appInit` 修掉 `if(!box) return` 陷阱 |
| 面板遮挡消息 | 用着别扭 | 消息区自动让位；可拖窄/关闭；宽度记忆 |
| 首屏能力清单未加载时误判开关 | 开关形同虚设 | `docpFromAnswer` 先 `capLoad()` 再决定（拉不到时按「默认全开」） |
| **`static/index.html` 的行尾陷阱（本次踩到）** | 整个文件显示为改动，diff 不可评审 | 该文件在索引里被标成 `-text`（binary），git 跳过行尾归一 → 与 blob(LF) 不一致时整文件 diff。本次已把工作区统一为 LF、索引恢复为 `i/lf w/lf`，真实 diff 收敛为 273/373。**建议**：另开一个改动加 `.gitattributes`（如 `* text=auto eol=lf`）根治，本次不做以免混进本 PR |
| 关掉预览会不会连带关导出 | 老师导不出东西 | 双向解耦用例锁住（`TestSessionDocPreview`） |
