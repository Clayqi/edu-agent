# 项目分析与优化建议

> 分析日期：2026-09-22；阶段 1 更新：2026-09-23  
> 范围：当前工作区代码、文档、Git 状态与单元测试；阶段 1 已完成权限确认闭环和测试修复。

## 结论摘要

这是一个功能完成度较高的本地单用户教育 Agent：以教材为事实源，已经覆盖答疑、教案生成、模板导入/编辑、PPT/Word 导出、会话、检索、长期记忆、WPS 集成与 Wiki 构建。优势在于教材引用约束、SQLite 会话持久化、降级机制和较广的单元测试覆盖。

当前不宜直接扩展为多人或公网服务。权限确认回归已经在阶段 1 解决，下一步应收紧本地文件能力，并把持续膨胀的网关与单页前端拆分。整体建议定位为“可继续迭代的本地桌面应用”，而非已经具备生产多租户条件的平台。

## 架构盘点

```text
浏览器单页界面（static/index.html，约 3,760 行）
        │ 同源 HTTP / SSE
FastAPI 网关（web_server.py，约 1,210 行）
        ├─ Agent A：教材检索、引用校验、答疑、多轮会话
        ├─ Agent B：教案规划、模板识别/填充、HTML/PPT/Word 导出
        ├─ Agent S：任务编排与派单
        ├─ SQLite：会话、长期记忆、权限策略
        ├─ Chroma：教材/派生知识库向量检索
        └─ 本地资源：PDF、模板、WPS、文件浏览与导出目录
```

代码主体约 8,245 行 Python。运行态通过 `.env` 与 `data/` 集中管理，主服务默认绑定 `127.0.0.1:5174`，这符合本地工具的安全边界。

## 发现的问题与优化优先级

### P0（阶段 1 已完成）：权限确认协议闭环

此前后端将写操作默认策略设为 `ask`，但前端没有统一处理服务端的 `gate: "permission"` 响应；模板测试也仍按旧的“直接执行”契约编写，导致 3 项失败。

阶段 1 已完成：

- 前端新增统一权限请求函数：首次被 `ask` 拦截时显示服务端动作说明，用户确认后带 `confirm: true` 重试。
- 项目创建、PDF 入库、Word/PPT 导出已接入统一权限请求。
- 权限策略文件改为跟随 `EDU_DATA_DIR`，不再写死仓库根目录下的 `data/`。
- 模板保存/删除测试现在分别验证“首次被闸门拦截”和“确认后执行”，并隔离测试权限文件。
- 相关 3 项失败已修复，全量 298 项测试以 `OK (skipped=2)` 结束。

后续 React 前端应复用相同协议：所有有副作用的请求都必须通过统一 API 客户端处理权限闸门，不允许各组件自行拼确认逻辑。

涉及：[web_server.py](../src/edu_agent/web_server.py)、[index.html](../static/index.html)、[test_template_rich.py](../tests/test_template_rich.py)。

### P0：本地文件能力的授权范围过宽

`/api/fs/list` 可枚举所有探测到的盘符，`/api/fs/mkdir` 可在这些盘中建目录；`/api/wps/download` 只按扩展名校验，任何本地 `.docx/.pptx/.pdf` 绝对路径都可被下载。服务目前只绑定 loopback，风险主要来自本机其他进程、恶意网页诱导及未来反向代理部署；一旦不再是严格的单用户本地运行，风险会显著放大。

建议：

- 将文件浏览根固定为 `EDU_FS_ROOT`，不要把“全部盘符”作为可访问边界；默认使用专用导出目录。
- 导出后建立短期文件登记表，以随机下载 ID 取代传入任意 `path`；同时校验真实路径和文件所有权。
- 对上传、模板、导出限制大小、类型、数量和生命周期；清理临时文件与过期导出。
- 在应用启动页和部署文档中明确“仅本机单用户使用，不可直接映射到局域网/公网”。若要多人使用，增加认证、用户隔离、CSRF 防护和审计日志。

### P1：记忆与“自建技能”需要可信度和提示词治理

长期记忆已支持显式添加、冲突处理、钉住、过期清理，方向合理；但当前 Web 服务固定使用 `MEM_PROFILE = "default"`，不同使用者会共享同一记忆库。自动抽取还会把模型输出写入长期记忆，必须避免模型误抽取或提示词注入污染。

自建技能的正文由模型回答写入本地文件，下一轮仅把“技能名称 + 描述”注入提示词，正文并不会按需读取或被程序执行。因此“下次自动按它做”的产品表述目前不能可靠兑现，同时描述本身仍可能污染后续提示词。

建议：

- 引入明确的本地用户/工作区 ID，替代固定 `default` profile；提供导出、删除与数据保留期限。
- 自动记忆默认改为“建议保存”，由用户确认后入库；至少给自动条目加来源、置信度和审核状态。
- 技能采用受限结构化 schema（目标、触发条件、步骤、禁止项），保存前校验；不把自由文本描述直接作为高优先级指令。
- 若要真正复用技能，后端按匹配结果读取经校验的正文，并以不可信参考资料的方式注入；否则把功能改名为“经验笔记”。

### P1：网关与前端单文件已成为维护瓶颈

`web_server.py` 同时承担模板、项目文件、SSE、会话、教材、PDF、WPS、记忆、技能、权限和预热；`index.html` 同时含页面、样式和大量业务逻辑。继续新增功能会提高回归率，且难以做接口级测试和权限审查。

建议按业务边界拆分，而非一次性重写：

```text
api/routers/  sessions.py  templates.py  chat.py  resources.py  memory.py  exports.py
services/     chat_service.py  template_service.py  export_service.py
static/       app.js  chat.js  template-editor.js  permissions.js  app.css
```

保留现有 URL 作为兼容层，先抽纯函数和 service，再拆路由。每一次拆分以现有测试与一个端到端冒烟用例守住行为。

### P1：运行数据与版本控制边界需要收口

`.gitignore` 已声明 `data/` 不入库，但 `chroma_db/` 二进制库仍被 Git 跟踪，且当前已有 SQLite/索引二进制改动。它会放大提交、制造平台差异并让代码审查失焦。`content/plans/` 也出现“已被跟踪但现已忽略”的历史产物。

建议将可重建的 Chroma 索引移至发布包、对象存储或首次启动构建流程；仓库只保留固定的源语料、索引版本清单和校验和。对已跟踪运行产物制定迁移计划（先备份、再移出索引，禁止直接删除用户数据）。

### P2：测试数量增加了，但缺少关键链路与自动化门禁

现有单元测试覆盖了检索降级、会话、模板、记忆、WPS 适配等核心函数，这是明显优势。但目前没有可见的 CI 工作流，也没有浏览器/API 集成测试覆盖权限确认、SSE 并行会话、文件路径边界、上传限制、数据迁移和重启恢复。

建议：

1. 将 `scripts/run_tests.sh` 作为唯一测试入口，并在 Windows CI 上执行。
2. 新增 FastAPI `TestClient` 集成测试：权限闸门、下载 ID、路径越界、模板保存/删除、上传失败清理。
3. 使用 Playwright 覆盖三条关键用户旅程：答疑、模板编辑保存、导出确认。
4. 固定少量离线检索回归集；真实 DeepSeek/Ollama/WPS 放到手动或受控 nightly 冒烟，避免把网络波动当作单测失败。

## 保持并强化的设计

- 教材引用、低置信度降级和图片公式防幻觉是教育场景的正确取舍，应保留并持续评测。
- `SessionStore` 使用 SQLite WAL、有限消息数和迁移留档，适合当前本地单进程产品。
- 权限模块采取“未知动作默认拒绝、写操作默认询问”的思想正确；阶段 1 已补齐前后端确认协议，后续应以集成测试守住该契约。
- WPS 不可用时走本地生成/WSL 后路，降低了环境耦合；但真实 WPS 验收仍应作为独立发布条件。
