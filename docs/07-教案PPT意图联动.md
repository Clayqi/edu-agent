# 教案 / PPT 意图联动（一期 v1.9.0 · 二期 v1.10 · 三期 v1.11.0）

老师问到「教案 / 课件 / PPT」时，对话里会多出一张**下一步选项卡**，给三条路：

- **① 生成教案模板** —— 让教案 Agent 把这节课**归纳成板块骨架**（含每个板块的填写提示与表格表头），
  存进模板库，以后任何一节课都能套用；
- **② 按模板生成** —— 从模板库里**选一个模板**（多个模板时给下拉），教案 Agent 严格按它的板块名称与顺序产出教案；
  产出后**自动按板块填进模板并载入教案中心**；
- **③ 填入教案中心**（二期）—— **不再花模型调用**，把会话里已有的一份教案按标题填进模板对应板块，
  直接进教案中心继续改。会话里还没有教案时不出现这个按钮。

> 规划与取舍见 `docs/06-教案PPT意图联动计划书.md`；模板的导入与编辑见 `docs/05-教案模板导入与编辑.md`。
> 本文讲**已落地**的部分（一期 + 二期）。

## 1. 老师怎么用

问一句涉及教案的话即可，例如：

- 「帮我备一节 3.3 幂函数的课，要课件」
- 「这节函数的教学设计怎么做」
- 或先让教案 Agent 出一份教案，再问「给我整一份 PPT」

回答下方会出现「下一步」卡片：

| 按钮 | 点了会发生什么 | 耗时 |
|---|---|---|
| **① 生成教案模板** | 教案 Agent 归纳出板块骨架 → 提示条变成「已生成《X》：9 板块 · 3 表　**去教案中心编辑**」 | 约 10–20 秒 |
| **② 按模板生成** | 按下拉里选中的模板重新生成教案；**完成后自动填入教案中心**，提示条给出填充报告 | 与普通教案生成相同 |
| **③ 填入教案中心** | 不重新生成：把会话里这份教案按标题填进所选模板的板块，编辑器随即载入 | **1 秒内**（纯解析匹配，不调模型） |

- 模板多于 1 个时，② 旁边出现**下拉**，列出每个模板的「板块数」与是否「可编辑」（`rich`）；
- **选择会被记住**（`localStorage: edu_chat_tpl`），下次默认还是它；
- ① 生成完可以直接点「去教案中心编辑」跳到模板编辑器，改完「保存为模板」即可复用；
- ②③ 填入后卡片上会给报告：匹配几个、新增几个、几个板块没匹配到、几个还空着，并带「去教案中心编辑」入口。

### 两个安全阀

| 情况 | 行为 |
|---|---|
| 教案中心模板编辑器里**有未保存的改动** | **不覆盖**。弹提示并让老师先去处理（未保存的编辑比一次自动填入值钱） |
| ② 生成的内容太短（<80 字，解析不出板块） | 不填入，卡片上说明原因 |

② 填入后**不会抢视图**：内容已进编辑器并落了草稿，老师自己切到「教案中心」即可（自动跳页会打断正在看回答的人）。

## 2. 触发规则：两类信号，任一命中

判定在 `routing.involves_plan_topic(text, hits)`，返回 `(是否涉及, 原因)`：

| 原因 | 信号 | 例子 |
|---|---|---|
| `intent` | 问题里有 教案 / 备课 / 教学设计 / 课堂设计 / 课件 / **PPT** / 幻灯片 / 演示文稿 / slides / 说课 / 讲稿 / 导学案 / 教案模板 | 「这节教案怎么写」 |
| `retrieval` | **检索命中的片段**的来源名、标题、章节或正文开头里有上述词 | 老师上传过课件 PDF，按 `corpus=pdf:` 检索命中 |
| `plan_mode` | 派单结果是 **B（教案 Agent）**，无需信号，恒给 | 「帮我备一节 3.3 幂函数的课」 |

**零打扰**是硬要求：普通答疑（问一道题、问概念）**不出现**这张卡片。
`tests/test_plan_link.py` 里专门有一条「普通答疑不产生 options 事件」的回归。

**③ 的出现条件**另有一条：会话里**真有教案正文**（本轮是 B，或者更早出过教案）。没东西可填就不给按钮——
`plan_available` 由 `_last_plan_markdown(session_id)` 判定，有专门单测。

### 顺带修掉的两个派单漏判（`routing.PLAN_HINTS`）

- 「要 **ppt**」以前判成 A（词表里只有「课件」）；
- 口语「帮我**备一节** 3.3 幂函数的课」以前判成 A。

现已补齐：`ppt`、`幻灯片`、`演示文稿`、`slides`、`课件制作`、`说课`、`备一节`、`备一课`、`备这节课`。

## 3. 选项①「生成教案模板」是怎么产出的

`planner.make_template(topic, goal)`：一次 LLM 调用 → 结构化 JSON → 转成可编辑的富模板。
产出物满足「**骨架 + 填写提示 + 表头**」三要素（一期锁定的口径）：

- 板块骨架：只给板块名与顺序，**不写具体教学内容**；
- 每个板块下有一句**填写提示**（说明这个板块该填什么、有什么要求）；
- 表格类板块（教学过程、板书设计等）**带上表头**（如 环节 / 教师活动 / 学生活动 / 设计意图）；
- 存进 `content/templates/<id>.json`（`spec_version: 2`，`rich: true`），走 `template_rich.save_rich()`，
  **和「导入 .docx / 全量编辑」是同一套模型**，所以生成完能直接在教案中心改到每一段、每一格。

接口：`POST /api/plan/template`

```jsonc
// 请求：topic 留空时会话里最近一份教案的课题兜底（_last_plan_topic）
{"topic": "3.3 幂函数", "goal": "", "session_id": "...", "save": true, "set_current": false}
// 响应
{"ok": true, "template_id": "新授课通用教案模板", "name": "新授课通用教案模板",
 "stats": {"blocks": 9, "tables": 3}, "skeleton": "# …（markdown 骨架）", "path": "…json"}
```

实测：「帮我备一节 3.3 幂函数的课，要课件」→ 点① → **14 秒**产出《新授课通用教案模板》，
**9 板块 / 3 个表格板块**，带填写提示与表头，落库为可编辑模板。

> 一期不自动设为「当前模板」（`set_current: false`）——避免悄悄改掉 Agent B 的默认模板。
> 需要的话在教案中心点一下「保存为模板」即可。

## 4. 选项②「按模板生成」：修掉一个写死的 `default`

前端原先发 `/api/chat` 时 **`template_id` 恒为 `'default'`**，所以「选模板」这件事此前根本传不到后端。
现在：

- 新增 `CHAT_TPL` 变量 + `sendText(val, {preset, templateId})`；
- ② 按钮把下拉里的值传进去，并 `planOptsRemember()` 记住；
- 后端沿用既有链路：`/api/chat` → `_stream_planner` → `planner.make_plan(template=req.template_id)`，
  **后端一行没改**（这正是计划书 §5 说的「② 走既有管道」）；
- 回答结束后（`done` 事件）前端自动调用 `/api/plan/from-template`，把这份教案填进同一个模板。

jsdom 真 DOM 回归实测点击 ② 之后的请求体：

```
POST /api/chat                 {"text":"帮我备一节 3.3 幂函数的课","preset":"B","template_id":"高中数学_函数的概念_教案"}
POST /api/plan/from-template   {"markdown":"# 3.3 幂函数…（334 字全文）","template_id":"高中数学_函数的概念_教案"}
→ 编辑器载入 12 板块 / 18 段 / 6 表（真实原件升级后填充）
```

## 5. 选项③「填入教案中心」：解析 / 匹配 / 填充（`plan_sync.py`）

**不花模型调用**，纯文本结构转换。三步：

1. **解析** `parse_plan_markdown()`：把会话教案拆成「板块 + 内容项」——
   认 `# 课题`、`**板块名**`、`## `、`### 环节（约 X 分钟）`、列表、Markdown 表格；
   会剥掉会话消息里的 `**【Agent B · 教案 Agent】**` 标签前缀；首个板块标题之前的散句归入 `（开头）`，不当板块。
2. **匹配** `match_sections()`：标题**归一化**（去编号、去括号补注、去标点）+ **别名组**
   （作业设计↔作业布置、教材依据↔课标依据、教学重难点↔重点难点…）+ 字符 Jaccard 相似度，
   **贪心 1:1 分配**，阈值 **0.34**。
3. **填充** `fill_template()`：模板该板块是表格就按表格填（保留**真表头**——整行都是 ≤6 字短标签才算表头，
   把 `### 环节` 一环节一行替换掉模板里的示例行），否则逐条成段落并**套用模板该板块的字体/字号/颜色**。
   **模板的板块顺序、标题、标题格式一律不动**；没匹配到的板块保持原样；教案里多出来的板块**追加为新板块**（不丢内容）。

接口：`POST /api/plan/from-template`

```jsonc
// 请求：markdown 留空时会话里最近一份教案兜底；save=false 表示只回结果不落盘
{"markdown": "", "session_id": "…", "template_id": "高中数学_函数的概念_教案", "save": false}
// 响应
{"ok": true, "template": {…填充后的富模板…}, "template_id": "…", "template_name": "…",
 "template_upgraded": true,
 "report": {"title": "3.3 幂函数", "threshold": 0.34,
            "matched": [{"block": "七、教学过程（45 分钟）", "section": "教学过程", "score": 1.0, "filled": 6}],
            "unmatched_blocks": ["八、板书设计", "…"], "appended": ["核心知识"]},
 "blank_blocks": ["十一、教学反思（预案）"], "stats": {"blocks": 12, "paragraphs": 18, "tables": 6}}
```

**报告怎么读**（卡片提示与编辑器顶部用同一份数据）：

| 字段 | 含义 |
|---|---|
| `matched` | 匹配上并填了的板块（含相似度分数与填入的内容块数） |
| `appended` | 模板里没有、作为**新板块**追加的（教案里的特殊板块名，如「核心知识」） |
| `unmatched_blocks` | 模板里有、这次**没匹配到**的板块——**保持原样**，没被清空 |
| `blank_blocks` | **还空着**的板块（没有元素，或只剩模板占位文字/空表格）。显示时会把 `unmatched_blocks` 里的去掉避免重复数 |

编辑器顶部会因此多两条：一条灰的「⇪ 已从会话填入…匹配 N 个板块」，一条**黄条**列没匹配到与还空着的板块。
顺手把那句占位提示也统一了：① 生成的模板里，段落板块的填写提示现在同样带 `（填写提示）` 前缀
（原先只有表格板块带），一眼能分出「这是提示」还是「这是内容」，空板块判定也据此。

**边界**（照实说）：匹配是**标题层面**的——教案里的特殊板块名匹配不上会走「追加」，
**标题不会被自动改写成模板的叫法**；两列表格里没有「标签：」前缀的条目，标签列会留空。这些都能在编辑器里手改。

### 任何模板都能填（v1.10.1）

填充只需要**板块标题**，所以三类模板都能作为填入目标，响应里的 `template_source` 会说明走的是哪条：

| `template_source` | 情况 | 做法 |
|---|---|---|
| `rich` | v2 富模板（导入过 / 编辑过 / ① 生成过） | 直接用 |
| `upgraded` | v1 骨架，但 `content/templates/orig/` 里有原件 | 现场升级成富模板再填（原件标记不可删） |
| `skeleton` | v1 骨架且没有原件（**含内置 `default`**） | `plan_sync.rich_from_skeleton()` 用板块名现搭结构；表格板块表头从 note 还原 |

> 早先只有前两类能填，选到 `default` 会直接报「不是可编辑模板」——那是条死胡同，
> 而老师要的其实只是「把教案按这套板块排好」。现在内置 `default` 也能填：
> 实测 7 板块、5 个 1.0 命中。
>
> 另：把默认模板填好再点「保存为模板」，会写 `content/templates/default.json`；
> `get_template("default")` 已改为**同名存档优先**（文件不存在才用内置骨架），
> 否则会出现「教案中心显示填好的那份、Agent B 却还在用内置骨架」的错位。

## 6. 对话里的导出条与预览（三期）

教案类回答（Agent B / 总指挥出的教案）下方会多一条**导出条**，与教案中心**同一套实现**（`expViaServer` / `expPreviewSlides` /
`expDownloadHtml`，不是复制粘贴）：

| 按钮 | 做什么 | 实现 |
|---|---|---|
| **Word** | 经 WPS 导成 `.docx`（未落盘自动 python-docx 兜底） | `POST /api/wps/export` + `markdown` |
| **PPT** | 本地生成真 `.pptx`，**每个环节一页** | 同上，`kind:"pptx"` |
| **预览 PPT** | 先看会生成哪几页，**不写文件、不用 WPS** | `POST /api/plan/preview` |
| **HTML** | 教案 Agent 回答时服务端已落了一份网页版（`content/plans/<课题>.html`），直接给 | `/files/<文件名>` |
| **位置** | 选导出到哪个目录（与教案中心**共用**同一个记忆 `edu_dz_outdir`） | `openDirPicker` |

### 预览 = 将生成的（三期顺手修的一个真 bug）

原先 `pptx_native` 的 markdown 分支**只认 `## ` 标题**，而 Agent B 的教案用的是
`**板块名**` + `### 环节（约 X 分钟）`——于是「对话里导出 PPT」会出来一份**几乎空白**的 PPT
（只有封面）。现在抽出 `wps_export.slides_from_markdown()`，**预览与实际生成共用同一个解析**：

- 取页优先级：`###` 环节 > `**板块**` > `## ` 标题 > 整篇一页；
- 一环节一页（导入/建构/例题/小结…），时长单独取出，标题里不再重复「（约 5 分钟）」；
- 幻灯片上**去掉 `[1]` 引用角标**（投影给学生看的，角标是噪音）；
- **表格内容不进 PPT**（留给 Word）；
- 预览接口刻意**不查能力开关**：它不落盘、不碰 WPS，而导出仍然受开关约束。

实测（jsdom 真 DOM 回归）：「帮我备一节 3.3 幂函数的课」的教案 →
预览 **4 页：情境导入 / 概念建构 / 例题精讲 / 课堂小结**，无引用角标。

### 生成前预检

选了模板（或换模板）时，卡片提示会立刻告诉老师这次要做什么：

> 已选《高中数学_函数的概念_教案》：**20** 个板块（含 6 个表格） · 骨架模板 · 生成约 **1~4 分钟**，点②开始

`/api/templates` 的每项新增 `tables`（v2 数表格元素、v1 数表格板块），供这里用。

### 导出前置校验

两道闸门，都给人话：

1. **客户端**：`capWps()` 已知 WPS 能力被关掉 → 直接拦下，**不发请求**，提示「请到「MCP 服务」开启」；
2. **服务端**：`/api/wps/export` 返回 `gate:"capability"` → 前端把它翻译成同一句人话，
   而不是把 `{"ok":false}` 静默吞掉。

### 设置开关

「设置 → 教案 → **教案选项自动提示**」可以关掉那个选项卡（`localStorage: edu_plan_auto`，默认开）；
同一处还能看到当前导出位置。关掉后对话完全回到原来的样子，重新打开即恢复。

## 7. 提示词的两处收口

| 位置 | 改了什么 | 为什么 |
|---|---|---|
| `prompts.SYSTEM_PROMPT` 第 8 条 | A（课本教练）**不越界写教案**，改为引导用户点这两个按钮 | 以前老师问「教案怎么写」会得到一份半成品教案，和 B 的产出打架 |
| `prompts.PLAN_TEMPLATE_GUARD` | 骨架约束从 planner 内联**提到 prompts 统一维护**，并补第 3 条「**本板块教材依据不足，请补充**」 | 原先只有「不得增删板块」，模型碰到教材没覆盖的板块会硬编内容 |

顺带修掉 `prompts.JSON_INSTRUCTION` 里 `\subseteq` / `\frac` / `\log` 的无效转义（历史遗留 `SyntaxWarning`），
行为不变。

## 8. 事件协议（向后兼容）

生成层（`generate.ask_stream`）在 `done` 事件里带一个信号字段：

```jsonc
{"t":"done", ..., "plan_options": {"suggest": true, "reason": "intent"}}  // 不涉及教案时为 null
```

`web_server._with_plan_options()` 把 Agent 流**原样透传**，收尾时按需补一个事件：

```jsonc
{"t":"options", "kind":"plan", "reason":"plan_mode|intent|retrieval", "topic":"3.3 幂函数",
 "options":[
   {"id":"gen_template","label":"生成教案模板","hint":"…"},
   {"id":"use_template","label":"按模板生成","hint":"…",
    "templates":[{"template_id":"…","name":"…","blocks":9,"rich":true}], "current":"…"},
   {"id":"fill_center","label":"填入教案中心","hint":"…"}   // 仅当会话里真有教案正文
 ]}
```

- 事件类型集合仍是 `{session,status,d,delta,done,error,options}`——**老前端会忽略不认识的 `t`**，所以是加法；
- A / S 派单只有 `suggest=true` 才补；B 恒补（`reason=plan_mode`）。

## 9. 边界（还不做的）

- **PPT 美化**：现在只做「封面 + 每环节一页 + 要点」，不做配色模板、配图、动画。
- **图片生成**：教案里的插画/示意图不生成。
- 会话教案的**多模板对比**（一份教案同时套不同模板看效果）。
- WPS 适配层（`tools/wps_spike/`、`deploy/`、`mcp_servers/`）三期一行未动。

## 10. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 涉及教案但**没有**卡片 | 派单可能是 A 且检索也没命中。看响应流里有没有 `options` 事件；`routing.PLAN_HINTS` / `TOPIC_HINTS` 是唯一改动点 |
| 普通答疑却**出现**了卡片 | 检索片段里含「教案/课件」等词（`reason=retrieval`）。卡片标题会写明原因 |
| 完全不想要卡片 | 设置 → 教案 → 关掉「教案选项自动提示」 |
| 没有 ③ 按钮 | 会话里还没有教案正文（`plan_available=false`）。先让教案 Agent 出一份 |
| 卡片下拉预选的是 `default`，不是我在教案中心选的模板 | v1.10.1 已修（`CHAT_TPL` 初值不再是 `default`；记忆里失效的模板也会回退到服务端 `current`）。若仍不对，看 `/api/templates` 的 `current` |
| 点① 报「缺少课题」 | 会话里没有教案回答、也没传 `topic`；先问一句或直接传课题 |
| 点① 报「模型没有产出板块」 | 模型这一轮 JSON 没解析出来，再点一次即可 |
| 点② 出来的教案跟模板对不上 | 确认下拉里选的模板；模板本身的板块名在教案中心可见（`content/templates/<id>.json`） |
| 点③ 报「没有模板 X」 | 该模板已被删除，重新选一个 |
| 点③ 提示「教案中心有未保存的修改，没有覆盖」 | 这是**故意的**保护。去教案中心保存或退出模板模式，再点一次 |
| 填完有些板块是空的 | 看黄条：`没匹配到`＝标题对不上（内容不会丢，保持原样）；`还空着`＝模板那块本来就空。都可在编辑器里手改 |
| 导出条只有 Word/PPT 有用，HTML 说「没有服务端 HTML」 | 那条回答不是教案 Agent 出的（服务端只在 B 出教案时落 HTML 页）。用 Word/PPT 即可 |
| 点导出提示「WPS Office 服务已关闭」 | 去「MCP 服务」把 WPS 打开；或先点「预览 PPT」看内容（预览不需要 WPS） |
