## 1. 职责边界（MCP / Skill / 前端 DOM 严格区分）

| 层 | 是谁 | 只负责 | 明确不做 |
|---|---|---|---|
| **MCP** | `wps-office`（第三方 wps-skills） | **只负责【导出】**：把 payload 落盘成磁盘 `docx/pptx` | 预览链路**全程禁止调用** |
| **Skill** | `doc-session-preview`（注册进 `capabilities.py`） | **业务开关**：控制 Agent 是否**输出结构化 payload** 触发面板渲染 | **不绘制任何 DOM 界面** |
| **前端 DOM** | `#docPanel`（浏览器内执行） | 4 个 Tab 的**内存渲染**（无 iframe、原生 DOM、不落地文件） | 不改外壳、不新增下载入口 |

- 关闭 **Skill**：Agent 不再推送文档数据到侧边面板 → 面板内容清空；**导出功能不受影响**。
- 关闭 **MCP**：预览**完全正常**；点导出被能力拦截并提示，预览不受影响。

## 2. 数据流

```
①用户在对话输入备课指令
        ↓
② Agent 生成教案结构化 payload（沿用 wps 导出 payload 结构）
        ↓
③ Agent 推送 payload 到前端 → 填充进**当前已存在的** #docPanel 容器 → 自动刷新对应 Tab
        ↓
④ Tab 切换 = 换渲染器，读**同一份内存 payload**（数据源统一，切 Tab 不重新取数）
        ↓
⑤ 点右上角【下载▾】→ 前端把当前内存 payload 提交 /api/wps/export
   → 后端经 wps-office MCP 落盘生成文件 → 再执行下载
```

**payload 形状**（沿用现有 wps 导出结构）

```jsonc
{
  "title": "3.3 幂函数",
  "grade": "重点班 45 分钟",
  "markdown": "# 3.3 幂函数\n\n**教学目标**\n- 理解幂函数的概念\n\n**教学过程**\n### 情境导入（约 5 分钟）\n…",
  "slides": [{"name":"情境导入","minutes":"5","bullets":["投影课本 p89 五个实例","学生写解析式"]}],
  "blocks": [{"title":"教学目标","level":2,"chars":43}],
  "stats": {"chars":222,"blocks":9,"slides":3,"minutes":20}
}
```

## 3. 逐 Tab 渲染设计

| Tab | 渲染器（新） | 输入 | 输出 | 依赖库 |
|---|---|---|---|---|
| **Markdown** | `docpRenderMd()` | `payload.markdown` | **marked** 解析 → 富文本 HTML，**DOMPurify** 过 XSS | `marked` + `dompurify` |
| **文档**（Word 样式） | `docpRenderDoc()` | `payload`（或导入的 `.docx`） | 类 Word HTML：标题层级 / 正文缩进 / 表格边框 / 页边距感；**仅基础排版，高级 Word 样式降级** | **`mammoth.js`**（.docx→HTML）＋ `docpRichHtml()` 兜底 |
| **幻灯片** | `docpRenderSlides()` | `payload.slides` → `docpBuildDeck()` | **pptxgenjs 前端内存生成 PPT 页面** → 按同一份 deck 模型**分页渲染 HTML 幻灯片**；**前端不生成 pptx 磁盘文件** | **`pptxgenjs`**（内存）＋原生 DOM |
| **结构** | `docpRenderOutline()` | `payload` 原始 JSON | 板块大纲 + 字数统计 + **原始结构化 JSON**（可折叠 `<details>`） | 原生 DOM |

**统一约定**

- 数据源唯一：内存对象 `DOCP`；`docpSetDoc(payload)` 是**唯一入口**（Agent 推送 / 历史重载 / 导入 三条路都走它）；
- **无 iframe**、原生 DOM、`innerHTML` 内存渲染；**预览不落盘**；
- **XSS**：marked 输出**必须**过 DOMPurify；库不可用时降级为纯文本转义（安全优先）；
- 面板提示小字统一为：**「右侧为内存预览效果，实际排版以导出 WPS 文件为准」**（改文案，不动布局）。

## 5. 会话侧入口整合 + 每条回答的「生成文档」（本次新增需求）

### 5.1 现状：会话侧散着 4 个入口，其中两个在做同一件事

| # | 现在的位置 | 文案 | 实际落点 | 问题 |
|---|---|---|---|---|
| 1 | 计划选项卡卡片 | ① 生成教案模板 | 后端生成模板并落库 | 保留（这是能力按钮，不是跳转） |
| 2 | 计划选项卡卡片 | ② 按模板生成（＋模板下拉） | `/api/chat` 用所选模板重新生成 | 保留（能力按钮） |
| 3 | 计划选项卡卡片 | ③ **填入教案中心** | 其实进的是**右侧面板** | **名不副实**：写着"教案中心"，落点却是面板；而"教案中心"页面另有一套（编排台） |
| 4 | 卡片提示行 | 「在右侧预览里查看」 | `docpReveal()` 打开右侧面板 | **与 ③ 落点重复**；且只在 ③ 之后才出现，位置零散 |

> 另外：每条 AI 回答下方的操作行现在只有 `复制` ｜ `重新生成` 两个按钮，**没有"把这条回答变成文档"的入口**。

### 5.2 整合方案（会话侧不再有"跳去教案中心"的按钮）

| 现有 | 处置 | 为什么 |
|---|---|---|
| ③「填入教案中心」 | **改名「③ 按模板填入」**（id 仍为 `fill_center`，落点不变＝右侧面板） | 去掉"教案中心"字样：不再跳页；它真正的独特价值是**按模板板块填充**（标题匹配 / 追加 / 报告），能力保留 |
| 卡片提示「在右侧预览里查看」 | **删除** | 与"面板自动打开"重复，少一个入口 |
| ① 生成模板后的提示 | 保留纯文字（无跳转） | 已经是纯文字 |
| **会话侧任何"跳去教案中心"的按钮** | **不再新增**；统一走右侧面板 | 呼应 §0 红线：预览流程禁止跳转教案中心 |
| 教案中心（页面 + 编排台 + 导入 .docx） | **原样保留** | 上一轮已恢复；只是**会话侧不再提供跳过去的入口** |
| 每条回答的操作行 | **＋ 第三个按钮「生成文档」** | 见 §5.3 |

### 5.3 新功能：每条回答后的「生成文档」→ 连到右侧边框

**位置**：**每条 AI 回答**下方的操作行，变成三个按钮 ——

```
[复制]  [重新生成]  [生成文档]        ← 第三个是本次新增
```

`addActions()` 是唯一出口，所以**新回答**与**历史恢复的回答**都会自动带上（不用改两处）。

**点击行为**

1. 取该条回答原文 `raw`（若这条消息的 `meta.doc` 已存在，**直接复用**，省一次计算）；
2. `POST /api/session/doc-preview`（纯内存，毫秒级）拿回预览模型 `{title, markdown, blocks, slides, stats}`；
3. `docpSetDoc(model)` → **自动打开右侧面板**并渲染（默认落在「文档」Tab）；
4. 之后所有出口都在面板里：切 4 个 Tab 预览、【下载▾】导出 Word/PPT（走原有 WPS 链路）。

**边界与细节**

| 情形 | 行为 |
|---|---|
| `doc-session-preview` **关闭** | 按钮**置灰** + tooltip「会话文档预览已关闭（Skill 市场可开）」，点击不动作（与边界规则 2 一致：skill 关 = 面板不接数据） |
| `wps-office` **关闭** | **不影响**「生成文档」（预览不查 WPS 开关）；仅导出被拦 |
| 内容解析不出板块 | **不拦人**：面板显示空态，仍可切「Markdown」Tab 看原文 |
| 同一条回答重复点击 | 面板已有该文档 → **直接打开，不重复请求**（挂在 `el.__doc` 上） |
| 回答很短（答疑一句话） | 同样允许生成（答疑也能成文导出），不做长度门槛 |

**为什么放在"每条回答"而不是只放教案回答**：答疑（Agent A）的内容同样有价值（讲题步骤、概念梳理），
统一入口后老师不用记"哪类回答才有按钮"。

### 5.4 面板边缘把手（2026-09-19 追加，按你的选择改）

原先的「查看/导入文档」是**屏幕右下角的悬浮圆按钮**，与面板是两块分开的东西。现改为
**贴着右侧面板边缘的竖排把手**（还是同一个 `#docPanelFab`，只改外观与定位，面板内部一行未动）：

| 状态 | 位置 | 文字 |
|---|---|---|
| 没有文档 | 贴在**屏幕右缘**（`right:0`） | 导入文档 |
| 有文档、面板收起 | 贴在**屏幕右缘** | 查看文档 |
| 面板展开中 | 贴在**面板左边缘**（`right: calc(var(--docp-w,460px) + 14px)`，面板自身 `right:14px`） | 收起文档 |

- 竖排文字（`writing-mode: vertical-rl`）、深色圆角只在左侧两角，看起来就是"从面板边上长出来的把手"；
- 宽度用面板同一个 `--docp-w` 变量，**拖宽面板时把手自动跟随**，不需要额外同步代码；
- 三态切换仍由 `docpSyncFab()` 负责（第 336 行那个"外壳层"函数），收起/展开逻辑没变。

### 5.6 入口与预览窗口全部融进面板 + 预览文档可编辑（2026-09-19 第二轮反馈）

老师原话：「我要的是**可以进行编辑**的预览文档，把查看文档的按钮与预览窗口都给我融进侧边面板，
不然两个右边框冗余」。据此做了三件事：

**① 右侧只剩一条框（入口融进面板）**

| 之前 | 现在 |
|---|---|
| 面板外挂一个悬浮按钮/竖把手（`#docPanelFab`），展开时和面板并排 → 右边两条竖框 | **面板收起态就是它自己缩成的那条竖把手**（`#docPanel.dp-collapsed` + 面板内的 `#docPanelStrip`，宽 30px 贴在右缘） |
| 收起 = `display:none`，靠外挂按钮回来 | 收起 = 加 `dp-collapsed` 类（**不再 display:none**），点竖条即展开；展开后入口在标题栏（【导入】【下载▾】【位置】【×】） |

- `#docPanelFab` 元素与样式**整个删掉**；原来的 `docpSyncFab()` 改名 `docpSyncEdge()`，驱动竖条文案
  （没有文档=「导入文档」，有文档=「查看文档」）；
- `docpClose()` 换成 `docpCollapse()`：收起前 `docpEditFlush()` 把编辑落定。

**② 预览文档可以直接编辑**

- **文档页签 = 所见即所得**：正文容器 `contenteditable="true"`，上面一条工具栏
  （`B` / `I` / `H2` / `H3` / `• 列表` / `1. 列表` / `清格式`，走 `execCommand`，不引额外库）；
- **Markdown 页签 = 源码编辑**：从"只读富文本"改成 `textarea`，改完自动回流；
- **回流链路**：改动 400ms 防抖 → `dpHtmlToMd()`（自写的小转换器：标题/段落/加粗斜体/列表/表格/引用/代码）
  → `DOCP.markdown` → `POST /api/session/doc-preview`（**纯内存**）拿回新的板块 / 幻灯片 / 统计 / 标题；
  **正在编辑的页签不重渲染**（否则光标会跳），其他页签跟着刷新；
- **导出用改后的内容**：Word / PPT 走原链路（`markdown:` 分支）；HTML 若已改过，则**在浏览器内存里**
  用改后的正文现生成一份下载（服务端不落盘）；
- **改动留存**：镜像到 `localStorage: edu_docp_edit_v1|<会话>|<标题>`，
  刷新/切会话后**只在"原文没被别人改过"时**恢复（键里存了 `orig` 比对，避免张冠李戴）；没改动就不写。

**③ 幻灯片 16:9 预览也在面板里**

- 去掉「在新窗口看（16:9）」按钮（`expPreviewSlides` 那条新窗口路径不再被会话面板使用）；
- 幻灯片页签顶部是**面板内的 16:9 预览台**（`.dp-stage`）+ 上一页/下一页 + 页卡直接跳页，
  当前页高亮；`pptxgenjs` 仍只在内存里建 deck（**不 `writeFile`**）；
- 教案中心编排台的 **「预览 PPT」也送进同一个面板**（不再弹新窗口）。

> 边界没变：编辑只发生在**内存 + 浏览器 localStorage**，服务端不写盘、不调 WPS；
> `content/plans/` 只有点【下载▾】走 `/api/wps/export` 时才会新增文件。

```python
class DocPreviewReq(BaseModel):
    payload: dict | None = None      # Agent 下发的结构化文档
    markdown: str = ""               # 原始 Markdown（payload 缺 markdown 时用）
    session_id: str = ""


@app.post("/api/session/doc-preview")
def api_session_doc_preview(body: DocPreviewReq):
    """结构化文档 → 前端预览：**只透传**，无任何磁盘 IO、不调用 WPS MCP。

    与 /api/wps/export 是两条独立链路：
      · 本接口：payload → 原样回传（+ 派生页结构供幻灯片 Tab 用），内存计算；
      · 导出接口：同一份 payload → 落盘 docx/pptx，受 wps-office 开关约束。
    """
    payload = body.payload if isinstance(body.payload, dict) else {}
    md = str(body.markdown or payload.get("markdown") or "")
    if not md.strip():
        md = _last_plan_markdown(str(body.session_id or "").strip()
                                 or (_store.current_id() or ""))

    slides = payload.get("slides") or []
    if not slides and md.strip():
        try:
            slides = wps_export.slides_from_markdown(md).get("slides") or []   # 纯计算，不落盘
        except Exception:                                                      # noqa: BLE001
            slides = []
    blocks = payload.get("blocks") or _plan_blocks(md)                         # 纯文本处理

    minutes = 0
    for s in slides:
        try:
            minutes += int(s.get("minutes") or 0)
        except (TypeError, ValueError):
            pass
    return {
        "ok": True,
        "enabled": capabilities.session_preview_ready(),   # 前端据此决定是否渲染/清空
        "title": str(payload.get("title") or "").strip() or
                 (wps_export.slides_from_markdown(md).get("title") if md.strip() else "") or
                 "未命名文档",
        "payload": payload,          # 原样回传
        "markdown": md,              # 原样回传（Markdown Tab 的输入）
        "slides": slides,            # 幻灯片 Tab
        "blocks": blocks,            # 结构 Tab
        "stats": {"chars": len(md), "blocks": len(blocks),
                  "slides": len(slides), "minutes": minutes},
        "note": "内存预览：不落盘、不调用 WPS；需要落盘请走 /api/wps/export",
    }
```

        sl.addText((i + 1) + '. ' + (s.name || '') + (s.minutes ? '（' + s.minutes + ' 分钟）' : ''),

      b.disabled = false; b.textContent = '生成文档';
      showToast('生成文档失败', false);
    });
  };
  row.appendChild(b);
}

## 13. 实现说明（4 条技术前提，按此实现即可成立）

1. **CDN**：按要求以 CDN 主引入；同时保留「加载失败 → 回落 `static/vendor/` 同名文件」的兜底
   （仓库里 `marked.min.js`、`purify.min.js` 已有；mammoth / pptxgenjs 一并放 vendor 作兜底），
   这样断网/被墙时预览不白屏。
2. **mammoth 的输入**：它只接受 `.docx` 二进制，所以「文档」Tab 的链路是
   **导入的 .docx → mammoth 转类 Word HTML**；Agent 下发的结构化 payload 走**同一 Tab、同一外观口径**的
   等价渲染（`mdToWordHtml` / `docpRichHtml`）。两者都是"基础排版、高级 Word 样式降级"。
3. **pptxgenjs**：它导出的是 `.pptx`（无 HTML 导出能力），所以「幻灯片」Tab 的 HTML 分页
   由**同一份 deck 模型**渲染，`pptxgenjs` 负责在**内存里**构建这些页面（`addSlide/addText`，
   **不调用 `writeFile`、不生成磁盘文件**）。这样既用上了 pptxgenjs，又保证「预览 = 将导出」。
4. **库标签必须 `defer`，兜底要双保险**（本轮实测踩到并修掉）：
   - 4 个 CDN 标签原本是**同步脚本、放在 `<head>`**，断网/被墙时每个都要等网络超时，
     实测把整页初始化推迟到 **~3.3s**；这段时间内点「发送」「生成文档」都会被静默丢弃。
     改为 `<script defer …>` 后不再阻塞解析，面板渲染层本来就是**用到才读 `window.marked`**，不受影响。
   - `onerror="this.src='/static/vendor/…'"` 在真实浏览器可用，但**严格按规范的实现里
     "脚本已启动后再改 `src` 不会重新执行"**（jsdom 即如此），所以只靠它就可能是空网。
     因此再加一道 `dpEnsureLibs()`：渲染前检查 4 个全局，缺哪个就**自己插一个本地 vendor 脚本**，
     补齐后回调重渲染一次；最多补 2 轮，避免离线时反复插入死循环。
   - 两道网叠加后的实测结果：CDN 全失败时 4 个库全部就位（`marked/DOMPurify/PptxGenJS/mammoth = true`），
     库彻底拿不到时（harness 用 `requestInterceptor` 把 4 个库全 404）面板仍出内容、零运行时错误。
