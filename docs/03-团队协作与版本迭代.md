仓库：https://github.com/Clayqi/edu-agent
适用：George + 团队成员（含 AI 助手代劳）在这台机器上开发 `D:\教育agent`。

## 一、一句话结论

**主干 `main` 永远可跑；每人一个 `feat/<模块>-<内容>` 分支；自己的模块自己推分支 → 开 PR → 合到 `main`；每完成一次可交付就打个 tag（v1.5.0、v1.6.0…）。**
目录已经天然分层，按目录切块就不会互相踩。

---

## 二、分支模型（最小可用版，别上 GitFlow）

| 分支 | 用途 | 谁能推 |
|---|---|---|
| `main` | 主干，随时能跑、112 例测试全绿 | 只通过 PR 合并（建议开保护） |
| `feat/<模块>-<内容>` | 一个功能/一个修复一条，例：`feat/rag-rerank`、`fix/panel-label` | 该模块负责人 |
| `hotfix/<内容>` | 线上/演示现场急修，直接从 main 拉 | 谁在场谁修，修完立刻 PR |

**版本号**：跟界面显示的版本对齐（当前 `v1.4.0`）。每次可交付（演示、给老师试用、交付里程碑）打一个 tag：

```bash
git tag -a v1.5.0 -m "v1.5.0: 看原页浏览器 + 图片公式防幻觉"
git push origin v1.5.0
```

GitHub 上会自动出现 Release 页，把 CHANGELOG 里这一段贴过去即可。

## 三、目录分工表（按这个分就不会冲突）

| 模块 | 目录/文件 | 职责 | 负责人 |
|---|---|---|---|
| 教材/RAG 层 | `src/edu_agent/{ingest,pdf_import,pdf_upload,retrieve,bm25_index,ollama_embeddings,figdetect,page_image}.py`、`scripts/`、`chroma_db/`、`content/` | 抽文本、切块、向量化、检索、页码/原页图 | 待填 |
| Agent 生成层 | `src/edu_agent/{generate,prompts,graph,planner,supervisor,routing,session,memory,template_spec,plan_html,math_verify,mcp_tools}.py` | 答疑/教案/总指挥、Prompt、编排 | 待填 |
| 网关与前端 | `src/edu_agent/web_server.py`、`src/edu_agent/host/store.py`、`static/`、`start_*.cmd` | HTTP 接口、会话持久化、界面 | 待填 |
| 测试与文档 | `tests/`、`docs/`、`README.md`、`CHANGELOG.md` | 112 例套件、交付文档 | 待填 |
| 教材库变更 | `chroma_db/`、`content/structured_auto/` | **只能一个人改**（二进制，多人同改必冲突） | 待填 |

规则（三条，记住就够）：
1. **自己的模块自己推**；要动别人的模块，先在群里说一声。
2. **共享文件改动前先 `git pull --rebase origin main`**：`README.md`、`static/index.html`、`web_server.py`、`prompts.py` 是热点文件。
3. **别提交这些**（`.gitignore` 已挡）：`.env`、`data/`、`model_cache/`、`.venv/`、`static/*.bak-*`。
4. **`chroma_db/chroma.sqlite3` 会"假脏"**：读过一次向量库（问答/脚本/单测都算）sqlite 就重写该文件，`git status` 显示 `M` 但**内容没变**（片段数 151、元数据一致）。
   不更新教材库时直接丢弃：`git checkout -- chroma_db/chroma.sqlite3`。
   只有教材真变了（重新 ingest / 回填元数据）才提交它，且由教材库负责人一个人提交。

## 四、第一次拉代码（含国内网络方案）

**有 Clash（推荐）**：
```bash
git clone https://github.com/Clayqi/edu-agent.git
cd edu-agent
git config http.proxy http://127.0.0.1:7897
git config https.proxy http://127.0.0.1:7897
# 关掉 Clash 后如报错，执行：git config --unset http.proxy && git config --unset https.proxy
```

**没有 Clash 的团队成员（三个可用通道，已实测）**：
1. 让有代理的同学把仓库整包给他：
   `https://ghfast.top/https://github.com/Clayqi/edu-agent/archive/refs/heads/main.tar.gz`（HTTP 200，实测可用；只含文件、不含 git 历史）
   拿到后 `git init && git remote add origin ...`，之后按第五节的流程走。
2. **Gitee 镜像**：在 Gitee 用「导入 GitHub 仓库」建一个镜像（由 Gitee 服务器去拉，国内 clone 很快）。约定：Gitee 只做只读镜像，正式提交仍回 GitHub。
3. 小改动直接发 patch：`git format-patch origin/main --stdout > xx.patch`，对方 `git am xx.patch`。

## 五、日常迭代流程（每人一遍，照抄）

```bash
# 0) 开工前先把主干拉到最新
git checkout main && git pull --rebase origin main

# 1) 开自己的功能分支（名字带模块，方便认领）
git checkout -b feat/rag-rerank

# 2) 改代码……改完先跑测试（这一步别省）
.venv/Scripts/python.exe -m unittest discover -s tests -p "test_*.py"     # 期望 Ran 112 tests, OK
#    改了前端就刷新浏览器自测；改了 prompts/generate/web_server 记得重启 5174

# 3) 提交（消息写清"改了哪块、为什么"）
git add -A
git commit -m "feat(rag): rerank 双通道默认开启，检索命中提升"

# 4) 推自己的分支（推到 main 同名分支，别直接推 main）
git push -u origin feat/rag-rerank

# 5) 开 PR（网页直达，把 <你的分支名> 换掉）
#    https://github.com/Clayqi/edu-agent/compare/main...feat/rag-rerank?expand=1

# 6) 合并后清分支
git checkout main && git pull --rebase origin main && git branch -d feat/rag-rerank
```

**提交消息格式**（`type(模块): 做了什么`）：
`feat(rag)` 新功能 · `fix(ui)` 修 bug · `docs(readme)` 文档 · `test` 测试 · `chore` 杂务。
一句话能说清"为什么改"比"改了啥"更重要。

## 六、合并、冲突与发布

- **合并**：PR 里至少一位同学看一眼（看 diff 就行），确认测试全绿再点 Merge（用 **Squash and merge**，main 历史干净）。
- **冲突**：谁的分支冲突谁解决：
  ```bash
  git checkout main && git pull --rebase origin main
  git checkout feat/xxx && git rebase main
  # 冲突处选正确的实现，改完 git add <文件> && git rebase --continue
  ```
  冲突涉及别人的模块 → 拉上模块负责人一起看，别单方面覆盖。
- **发布**：更新 `CHANGELOG.md`（新版本一段）→ 打 tag（见第二节）→ 推 tag。
- **保护 main（建议现在开）**：仓库 → Settings → Branches → Add branch protection rule
  直达：https://github.com/Clayqi/edu-agent/settings/branches
  勾：Require a pull request before merging；可选 Require status checks（以后接 CI 再加）。

## 七、这台机器的坑（George 专用）

1. **本地分支叫 `master`、远端叫 `main`** —— 已改名为 `main`（2026-09-10），以后直接 `git push` / `git pull` 即可；老笔记里若见到 `git push origin master:main`，那是旧写法。
2. **push 必须走 Clash**：直连 github.com 会被掐。代理只在需要时挂：
   `git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push`
3. **推完要验**，别信"push 成功"的自报：
   `git ls-remote origin main` 对一下 SHA，或从公网侧读文件：
   `https://ghfast.top/https://raw.githubusercontent.com/Clayqi/edu-agent/main/README.md`
4. **多 AI 并行施工**（Claw / Codex / dsh / WorkBuddy 同时动 `D:\教育agent`）→ 动文件前先看 mtime，并遵守上面的模块归属；`static/index.html` 这种热点文件一次只让一个会话动。
5. **教材库（chroma_db）是二进制**：多人同时改必然冲突，约定由一人负责、改完立刻提交并告知。另注意它会"假脏"——读过一次向量库 sqlite 就重写该文件（内容不变、git 显示 `M`），不更新教材时用 `git checkout -- chroma_db/chroma.sqlite3` 丢弃即可。
