## 1. 结论

当前 UI 的桌面主流程可以展示，但仍有 **6 个高优先级问题、8 个中优先级问题、3 个低优先级问题**。最需要先处理的是：

1. 固定宽度的三栏结构在平板和窄屏下直接压垮主工作区；
2. 右侧面板存在异步竞态，内容会重复，甚至串入另一个页签；
3. 设置页的“权限”开关与真实权限系统无关，会给用户造成错误的安全预期；
4. 题库、练习和课程页的大部分主按钮只是静态外观；
5. 教师/学生角色切换存在越界页面和文案不同步；
6. 多处看起来可点击的全局按钮没有任何行为。

浏览器控制台在本次巡检路径中没有产生 `error` 或 `warn`，但这不代表交互正确：多数问题属于逻辑未接线、状态竞态和布局缺陷，不会抛出 JavaScript 异常。

## 4. 详细问题

### UI-001：三栏固定宽度导致平板/手机主区不可用（P1）

**现象**

- 左栏固定 `252px`，普通右栏固定 `300px`；
- 文档右栏默认可扩至 `680px`；
- CSS 中没有任何 `@media` 响应式断点；
- 主区域仅依赖 `flex: 1; min-width: 0` 被动压缩。

**实测数据**

| 视口 | 左栏 | 主区 | 右栏 | 结果 |
|---|---:|---:|---:|---|
| 1440px | 252px | 888px | 300px | 可用 |
| 1024px | 252px | 472px | 300px | 教案双栏内部宽 690px，被压在 457px 容器中 |
| 1024px + 文档面板 | 252px | **92px** | 680px | 主工作区几乎消失 |
| 约 646px | 252px | **94px** | 300px | 对话输入区宽度可降到 0 |
| 480px | 252px | 0px 附近 | 300px | 页面总宽约 552px，出现横向溢出 |

**代码位置**

- `static/index.html:45`：`.sidebar{width:252px}`；
- `static/index.html:383`：`.sidepanel{width:300px}`；
- `static/index.html:429`：文档面板 `680px`；
- `static/index.html:242`：教案双栏最小列宽 `340px + 300px`。

**建议**

- `>= 1200px` 保留三栏；
- `768–1199px` 默认折叠左栏，右栏改为可覆盖抽屉；
- `< 768px` 主区独占宽度，左右栏都用全屏/半屏抽屉；
- 文档面板宽度用 `min(680px, 100vw)`，并给主区保留最小可用宽度；
- 教案中心在小于约 900px 时改为单列上下布局；
- 加 Playwright 断点测试，至少覆盖 1440、1024、768、390 四档。

**验收标准**

- 390px 宽度无页面级横向滚动；
- 主输入框在所有断点下宽度不少于可视区域的 80%；
- 打开文档面板时主内容仍可操作，或明确切换为覆盖式抽屉。

### UI-002：右侧面板异步响应跨页签污染、重复追加（P1）

**复现方式 A：跨页签污染**

1. 打开右侧“状态”；
2. 在状态接口完成前立即切到“知识源”；
3. 等待约 4 秒；
4. “知识源”底部出现本应属于“状态”的 `MCP / Skill` 卡片。

实测结果中，“知识源”页签内容变成：教材、上传 PDF、`MCP / Skill` 三组卡片。

**复现方式 B：重复卡片**

连续触发两次状态渲染，旧请求和新请求都会执行 `insertAdjacentHTML`，可出现两个 `MCP / Skill` 卡片。

**根因**

`spRenderTerm()` 每次先重写 `spBody.innerHTML`，随后并行发起多个异步请求。请求完成后直接向当前的 `spBody` 追加内容，没有：

- 渲染代次 token；
- 当前页签校验；
- `AbortController`；
- 统一的单次提交；
- 旧请求清理。

位置：`static/index.html:1190–1260`。

**建议**

为每次渲染生成 `renderId`，所有回调写入前验证：

```js
const id = ++sidePanelRenderId;
const data = await Promise.allSettled([...]);
if (id !== sidePanelRenderId || spView !== 'term') return;
spBody.innerHTML = renderStatus(data);
```

优先采用“收齐数据后一次性渲染”，避免多个异步分支分别改同一个 DOM。

### UI-003：设置页权限开关是假的（P1）

**现象**

设置弹窗显示“读取文件、写入文件、执行命令、联网检索”四个权限开关。点击时只切换 `.on` CSS 类：

```js
t.addEventListener('click', function(){ t.classList.toggle('on'); });
```

它们不会调用真实的：

- `GET /api/permissions`；
- `POST /api/permissions/set`；
- `permissions.set_policy()`。

因此，用户即使关闭“写入文件”，后端动作策略仍可能保持 `ask` 或 `allow`。这会产生错误的安全预期。

同一弹窗中的“主题、语言、用户名”也只有视觉状态，没有真实保存或生效逻辑。

**建议**

- 权限页直接读取后端 `allow / ask / deny` 三态，而不是二态假开关；
- 写入后立即重新读取并展示“已保存”；
- 接口失败时回滚 UI，不允许只在前端乐观切换；
- 在完成接线前，隐藏权限开关或标注“尚未生效”，不要保留可误导的控件。

### UI-010：表单和自定义控件缺少可访问名称（P2）

**确认项**

- 教案中心每个环节的“分钟”数字输入框无 `label`、`aria-label`、`title` 或 `placeholder`；
- 设置页用户名输入没有关联 `<label>`；
- 设置页开关没有可访问名称，也不暴露 `aria-checked`；

- Skill 市场“+”按钮完全没有可访问名称；

- 所有交互元素优先使用 `<button>`、`<input>`、`<select>`；

- 时间输入命名为“第 N 环节时长（分钟）”；
- 拖拽手柄补 `role="separator"`、方向、当前值与方向键调整。

### UI-011：小字号文字颜色对比度不足（P2）

基于当前 CSS 色值与白色背景计算：

| 颜色 | 对比度 | 常见用途 | 结果 |
|---|---:|---|---|
| `#a1a1aa` (`--ink-400`) | 2.56:1 | 11–12px 辅助文字 | 不达 AA |
| `#3b82f6` (`--blue`) | 3.68:1 | 蓝色文字/链接 | 普通小字不达 AA |
| `#16a34a` (`--green`) | 3.30:1 | 状态文字 | 普通小字不达 AA |
| `#71717a` (`--ink-500`) | 4.83:1 | 次级文字 | 达到普通文本 AA |

WCAG AA 对普通文本通常要求至少 4.5:1。当前 `--ink-400` 在大量 11.5px 文案中使用，阅读压力明显。

**建议**

- 普通小字至少使用 `--ink-500`；
- 蓝/绿状态文本使用更深色阶，浅色只用于图标或大字；
- 引入自动对比度测试，避免主题改动后回归。

### UI-014：Git 工具是硬编码假界面（P2）

点击头像打开的 Git 工具中：

- “提交、提交并推送、推送”按钮没有真实事件；
- “包含未暂存的更改”和“107 个文件”也是静态文案。

这会让用户误以为界面读取了当前仓库，甚至误判提交已发生。

位置：`static/index.html:2720–2787`。

**建议**

- 未接入真实 Git API 前移除入口；
- 若保留原型，显著标记“演示数据，不会执行”；
- 真正实现后，提交成功必须返回 commit SHA，失败必须保留输入并显示错误。

---

### UI-015：页面切换不进入 URL/历史记录（P3）

所有主页面通过 `switchView()` 切换 `.active` 类，URL 始终保持 `/`，没有 `history.pushState`、hash 或路由层。

**影响**

- 无法复制 Skill、MCP 服务、教案中心等页面的直接链接；
- 浏览器后退不能返回上一个应用页面；
- 刷新后恢复的是后端当前会话，不一定是刷新前的页面；
- React 迁移时状态与路由边界会更难梳理。

**建议**

至少引入 hash 路由；React 改造时使用 React Router，并把项目、会话和页签状态映射为明确路由参数。

---

### UI-016：接口错误被静默吞掉（P3）

多处请求使用空 `catch` 或返回 `null`：

- 知识源读取失败时可能只是不显示卡片；
- 教材库读取失败时可能继续展示默认书名和 `?` 数量；
- 能力快照失败时可能继续使用旧 `CAP`；
- 右栏的部分失败没有重试按钮。

用户无法区分“没有数据”和“加载失败”。

**建议**

统一四态组件：`loading / success / empty / error`，错误态显示简短原因和“重试”。旧数据继续展示时要标注“数据可能已过期”。

---

### UI-017：横向溢出没有可见恢复路径（P3）

480px 宽度下页面内容宽度约 552px，主区可被压到接近 0。由于 `body{overflow:hidden}`，部分超出内容不会以常规页面滚动方式恢复；用户必须知道先手动收起侧栏或右栏，但界面没有自动提示。

该问题与 UI-001 同源，单列出是因为它会造成“页面看起来消失”的恢复性问题。

## 5. 阶段性修复顺序

### 第一阶段：先恢复可信和可用（建议 1–2 天）

1. 修复 UI-002：右侧面板渲染增加代次校验和一次性提交；
2. 修复 UI-003：隐藏假权限开关，或直接接入 `/api/permissions`；
3. 修复 UI-005：角色切换统一路由守卫与文案派生；
4. 修复 UI-006：移除/禁用所有死按钮；
5. 为题库和课程页未完成的按钮加禁用态和说明。

### 第二阶段：建立响应式骨架（建议 2–4 天）

1. 三栏改为“桌面固定 + 平板抽屉 + 手机单栏”；
2. 教案中心在小屏改为单列；
3. 文档预览在窄屏使用覆盖式全高抽屉；
4. 增加四个断点的视觉回归测试。

### 第三阶段：补齐交互闭环（建议按业务拆分）

1. 完成学生答题最小闭环；
2. 完成题目生成/组卷最小闭环；
3. 完成课程继续学习/学习计划入口；
4. 设置主题、语言、用户名要么真实实现，要么暂时移除；
5. 删除硬编码 Git 原型或接入真实仓库状态。

### 第四阶段：可访问性与路由（建议 2–3 天）

1. 弹窗语义、焦点管理、Esc、焦点归还；
2. 表单 label、开关语义、非语义点击元素整改；
3. 调整低对比度色阶；
4. 增加键盘测试与 axe 扫描；
5. 建立真实路由和刷新恢复策略。

## 6. 建议增加的自动化测试

### 6.1 响应式

- 1440×900：三栏正常；
- 1024×768：主区不低于产品定义的最小宽度；
- 768×1024：侧栏/右栏为抽屉；
- 390×844：无页面级横向溢出。

### 6.2 异步竞态

- 状态 → 知识源快速切换后，知识源 DOM 中不得出现 `MCP / Skill`；
- 连续进入状态页两次，`MCP / Skill` 卡片数量必须为 1；
- 请求失败后必须出现 error state 和重试按钮。

### 6.3 角色

- 教师在教案中心切学生，必须跳到 AI 答疑；
- 学生进入练习页，标题必须为“我的练习”；
- 学生不可通过残留 DOM 或直接路由进入教师专属页。

### 6.4 控件行为

- 每个可见按钮必须满足之一：产生业务行为、进入明确页面、展示菜单/弹窗、或处于 disabled；
- 禁止“可点击样式 + 无事件 + 无反馈”；
- 权限设置后重新加载页面，策略保持一致并与后端返回相同。

### 6.5 可访问性

- 所有可见按钮、输入和开关都有唯一可访问名称；
- 所有弹窗有 dialog 语义并通过键盘关闭；
- Tab 顺序覆盖全部核心动作；
- 普通文本对比度不低于 4.5:1。

## 7. 建议的完成定义

下一轮不应只以“页面能打开”作为完成标准。建议 UI 阶段性验收同时满足：

- 关键页面在四个断点下可操作；
- 所有可见主按钮都有明确结果；
- 无跨页签异步污染；
- 教师/学生页面严格一致；
- 权限 UI 与后端策略一致；
- 控制台无错误；
- 核心路径可完全用键盘完成；
- 自动化测试覆盖响应式、竞态、角色和权限四类高风险场景。
