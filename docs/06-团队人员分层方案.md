# edu-agent 团队人员分层方案（2026-09-11）

仓库：https://github.com/Clayqi/edu-agent （public，默认分支 main）
本地路径：`D:\教育agent`
配套文档：`docs/03-团队协作与版本迭代.md`（流程）、`D:\hermes\edu-agent-团队授权与权限配置.md`（怎么加人）

---

## 零、先说结论

1. **这个仓库现在最多健康容纳 4~5 个人**，不是人数问题，是结构问题：有 3 个"巨型单点文件"+ 8 个"共享底座模块"，人再多就是排队改同一批文件。
2. **分层不能按人数平均切，要按依赖方向切**：谁被谁引用得多，谁就只能有一个 owner。
3. **你现在分层是 0/4 落地**：协作者只有你自己、main 未保护、没有 CODEOWNERS、没有 CI。分层目前只是文档里的口头约定，GitHub 不会替你执行。
4. 唯一能把"分层"从口头变成机制的钥匙是 **CODEOWNERS 文件**（把"哪个目录归谁审"写进仓库，GitHub 自动指派审查人）。本文末尾给了可直接粘贴的全文。

## 二、分层原则（三条，别违背）

1. **按依赖方向分层，不按人头平均分**。被 4 个以上文件引用的模块 = 底座层，只能一个人 owner。
2. **分层的粒度是"文件"不是"人"**。先把仓库切成互不重叠的文件组，再把人填进去；切不开的地方就是瓶颈。
3. **二进制/热点文件单人锁**。`chroma_db/`、`content/structured_auto/`、`static/index.html` 各自只能有一个提交人。

## 三、四层模型

```
L0 所有者（Owner）        1 人   —— 合并 main、打 tag、发 Release、改仓库设置
L1 底座/接口 Owner        1 人   —— 7 个共享底座 + web_server 契约
L2 模块负责人（3~4 人）           —— 各自一条业务轨道，互不重叠
L3 贡献者 / AI 会话       不限    —— 只提 PR，不能直推
```

### 权限映射（GitHub 只有这 5 种角色，没有"自定义角色"）

| 层 | GitHub 角色 | 能给的操作 |
|---|---|---|
| L0 | **Admin** | 全部（只你自己） |
| L1 底座 Owner | **Maintain** | 能改仓库设置、能合任何 PR |
| L2 模块负责人 | **Write** | 推分支、开 PR、审查、合 PR |
| L3 贡献者（人） | **Write 或 fork 模式** | 走 PR，但 CODEOWNERS 会卡住他改别人模块 |
| L3 试用老师 / 只报 bug | **Read + Triage** | 只看代码、提 issue |
| AI 会话（Codex/dsh/WorkBuddy） | 用你的账号 = **Admin 级** | **必须靠 CODEOWNERS + 保护规则来约束**，没有别的锁 |

> 注意：AI 会话共用你的账号，权限上等同于你 —— 这正是必须写 CODEOWNERS 的原因。

## 四、五条轨道 → 层次映射表（这就是"怎么给人分层"）

| 轨道 | 归哪层 | 文件（实测） | 规模 | 编制建议 |
|---|---|---|---|---|
| **底座/契约** | L1 | `config, logsetup, session, prompts, graph, generate, host/store, web_server` | ~1,800 行 | **1 人独占**（建议你自己，或最懂全局的人） |
| **A 教材/RAG** | L2 | `ingest, pdf_import, pdf_upload, retrieve, bm25_index, ollama_embeddings, figdetect, page_image, preprocess` + `scripts/` + `content/` + `chroma_db/` | ~1,200 行 | 1 人（兼教材库唯一提交人） |
| **B 生成/编排** | L2 | `planner, supervisor, routing, memory, math_verify, grounded, mcp_tools, chat` | ~740 行 | 1 人（依赖 L1，改动要先对齐底座） |
| **C 教案模板/PPT** | L2 | `template_spec, plan_html` | ~300 行 | 1 人（新功能发力点，v1.6.0 编排台就在这） |
| **D 前端界面** | L2 | `static/`、`*.cmd`、`run_ui.ps1` | 147 KB 单文件 | 1 人独占（热点锁） |
| **E 测试/发布** | L1 兼 或 L0 兼 | `tests/`、`CHANGELOG.md`、`.github/`、`docs/` | ~1,100 行 | 人少时由 L0/L1 兼；≥5 人时单设"发布把关人" |

**注意 A~E 里真正能并行、互不踩的只有 A / B / C / D 四条**（E 是公共职责）。教材库的"单人锁"不是一条人力轨道，它是 A 的附庸。

## 五、按团队规模，分层怎么落（同一套层的伸缩）

| 人数 | 怎么填 |
|---|---|
| **2 人** | 你 = L0 + L1底座 + D前端；成员 A = L2-A（RAG） + L2-C（教案） |
| **3 人** | 你 = L0 + L1（含 web_server）；A = L2-A RAG；B = L2-B 编排 + L2-C 教案；D 前端由你和 A/B 轮流（一次一人） |
| **4~5 人** | 你 = L0 + L1；A = RAG+教材库；B = 编排；C = 教案/PPT；D = 前端（独占）；E 测试发布由你兼或轮值 |
| **6~8 人** | **必须先拆文件**（index.html 拆视图、web_server 拆 handler、generate 拆 provider），拆完才有位置；再增设独立 Release 把关人 + 教材库专人 |

判断依据：L2 四条轨道 + L1 一个人 = **5 个不相撞的位置**。第 6 个人开始，无论怎么分都会落进已有轨道 → 撞车。

## 六、AI 会话怎么摆进分层（你的实际情况）

你同时用 Claw / Codex / dsh / WorkBuddy 动 `D:\教育agent`，它们**共用你的 GitHub 账号，权限上等于 Admin**，是分层里唯一管不住的成员。三条硬规矩：

1. **AI 会话一律当 L3 贡献者用**：产出走分支 + PR，不许直接 `git push origin main`。
2. **热点文件一次只给一个会话**：`static/index.html`、`web_server.py`、`generate.py`、`prompts.py` 同一时间只允许一个 AI 会话在改。
3. **动文件前先看 mtime + `git status`**：确认没有别的会话正在写同一文件（避免互相覆盖）。

## 七、落地三步（把分层变成机制）

### 第 1 步：写 CODEOWNERS（3 分钟，最关键）

CODEOWNERS = 一份"哪个目录归谁审"的清单。写了它 + 开了 Require review，**谁改别人的模块，GitHub 自动把模块负责人拉进审查，不合不能进 main**。这是把第四章那张表变成强制执行的唯一办法。

文件位置：`.github/CODEOWNERS`（内容见附录，把 `<RAG负责人>` 之类换成真实 GitHub 用户名，中文占位符 GitHub 不认）

### 第 2 步：开 main 保护并勾上 CODEOWNERS 审查

https://github.com/Clayqi/edu-agent/settings/branches → Add branch protection rule，pattern 填 `main`：
- 勾 **Require a pull request before merging**
- 勾 **Require approvals → 1**
- 勾 **Require review from Code Owners** ← 分层借它生效
- 勾 **Do not allow bypassing the above settings**

### 第 3 步：加 CI（可选但强烈建议）

现在 112 例测试靠人手跑，PR 页面看不出来谁跑没跑。加一个 `.github/workflows/tests.yml` 跑 `python -m unittest discover -s tests`，PR 上会自动出现红/绿，**没测过的 PR 合不进去**。人一多，这个比任何规范都管用。

## 附录 B：`.github/workflows/tests.yml`（第 3 步用，Windows runner）

```yaml
name: tests
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]
jobs:
  unittest:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: pip install -r requirements.txt
      - run: python -m unittest discover -s tests -p "test_*.py" -v
```

## 一句话总结

**分层 = 先把仓库切成"1 个底座 + 4 条不重叠轨道"，再把人填进去；底座和三个巨型文件必须单人独占，这是这个仓库的物理上限（5 人）。把这张表写进 CODEOWNERS 并开 main 保护，分层才从"文档约定"变成"GitHub 强制"。**
