# edu-agent 团队授权与权限配置指南（2026-09-11）

仓库：https://github.com/Clayqi/edu-agent
配套文档：`D:\hermes\edu-agent-团队协作与版本迭代.md`（分支模型 / 目录分工 / 日常 PR 流程）
适用：George 给团队成员开仓库写权限，并把 main 保护起来。

---

## 一、一句话结论

给每个成员加 **Collaborator + Write 权限**（1 分钟一个），加完立刻**开 main 分支保护**——只加人不保护 main，等于给了所有人直推主干的权力，团队流程就白设了。

---

## 二、加协作者（你来操作，每人 1 分钟）

直达链接：https://github.com/Clayqi/edu-agent/settings/access

1. 点 **Add people**
2. 填对方的 **GitHub 用户名**（或他注册 GitHub 用的邮箱），角色选 **Write**
3. 点 **Add** → 对方会收到一封邀请邮件

对方还没有 GitHub 账号：先让他去 https://github.com/signup 注册，然后把用户名发你。
（一个账号就能用，不用付费；public 仓库的协作者数量没有限制。）

---

## 三、对方要做的（2 步）

1. **接受邀请**
   - 点邮件里的 **View invitation**，或直接打开 https://github.com/Clayqi/edu-agent/invitations
   - 打不开是因为国内网络：需要挂 Clash（和 push 一样的前提）
2. **拉代码开始干活**
   - 有 Clash：按配套文档第四节的 `git clone` + 代理配置
   - 没有 Clash：用 ghfast 整包 `https://ghfast.top/https://github.com/Clayqi/edu-agent/archive/refs/heads/main.tar.gz`
   - 然后照配套文档第五节：开 `feat/<模块>-<内容>` 分支 → 跑测试 → 推分支 → 开 PR

---

## 四、立刻配套：给 main 开保护

直达链接：https://github.com/Clayqi/edu-agent/settings/branches
→ **Add branch protection rule**（或 Add classic branch protection rule）

- **Branch name pattern** 填：`main`
- 勾 **Require a pull request before merging**
  - 建议再勾 **Require approvals → 1**：这样"至少一位同学看一眼"变成强制，不能自己合自己的 PR
- 可选勾 **Do not allow bypassing the above settings**：把这个规则也套在你自己身上（推荐，保持一致）
- 点 **Create** / **Save changes**

效果：任何人都不能直接 `git push` 到 main，只能走 PR 合并。

---

## 五、权限级别怎么选（别给错）

| 角色 | 能做什么 | 给谁 |
|---|---|---|
| Read | 只能看代码、提 issue | 只读的旁观者 |
| Triage | 管 issue / PR 分类，不能改代码 | 需求整理、测试同学 |
| **Write** | **能推分支、开 PR、审查、合并 PR** | **团队成员就给这个** |
| Maintain | 能改仓库设置（webhook 等） | 一般不要给 |
| Admin | 最高权限，能删仓库、改可见性 | 只你自己 |

## 六、怎么验证授权真的生效

让对方推一个空测试分支：

```bash
git checkout -b test/hello
git commit --allow-empty -m "test"
git push -u origin test/hello
```

你在 https://github.com/Clayqi/edu-agent/branches 能看到这条分支 = 通了（删掉即可）。
他要是在 PR 页面能看到 Merge 按钮 / 能点 Review，也说明 Write 权限到位。

---

## 七、四个坑

1. **别把你的 token / 密码共享给成员** —— 每人用自己的账号。共享 token 出了问题算在你头上，而且 commit 记录里看不出到底是谁改的。
2. **邀请邮件容易进垃圾箱**。对方没收到时：你去 https://github.com/Clayqi/edu-agent/settings/access 找 **Pending invitations**，复制邀请链接直接发他更快。
3. **国内网络**：接受邀请、开 PR、点 Review 这些网页操作都要挂 Clash。
4. **public 仓库 ≠ 人人可写**：没被加为协作者的人也能 fork 后开 PR（外部贡献模式），但他推不了你仓库里的分支。要走配套文档那套团队流程（直接推 `feat/xxx` 到你仓库再开 PR），**必须加 Collaborator**。

---

## 八、以后再考虑（现在不用折腾）

成员超过 5 人、或以后要做第二、第三个仓库时：建一个 **Organization**（免费）→ 仓库转过去 → 建 team 批量授权。
优点：加人一次全仓库生效、权限分组管理、以后开源项目归属更正规。
现在几个人，用 Collaborator 就够了。
