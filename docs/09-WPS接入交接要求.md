# WPS MCP 接入 —— 交接要求（给组员）

> 场景：你已经在自己的本地把 WPS MCP 那套装好、跑通了。现在要把成果交给我（George）。
> 结论：**你本地的"环境"没法发给我**（WPS 加载项装在 WPS 应用里、node_modules 是你机器上编译出来的、路径写死在你机器上）。
> 所以要交的不是文件，而是三样：**代码走 PR + 环境写成步骤 + 证据留档**。
> 日期：2026-09-11 ｜ 仓库：https://github.com/Clayqi/edu-agent

## 一、交给我的三样东西（缺一样不算交付）

### 1) 代码 —— 走 GitHub，不许发压缩包 / 微信截图

- 从 `main` 拉分支：`git checkout -b feat/wps-adapter`
- **只提交你自己写的适配层**，例如：
  - `src/edu_agent/wps_tools.py`（仿 `src/edu_agent/mcp_tools.py`：stdio 短连接 + 白名单 + 失败兜底）
  - `tests/test_wps_tools.py`（白名单拦截 + 无 WPS 环境时自动 skip）
  - 安装脚本（如 `deploy/setup_wps_mcp.cmd`）
- 推分支 → 开 PR（页面直达：`https://github.com/Clayqi/edu-agent/compare/main...feat/wps-adapter?expand=1`）
- **注意：不要把 wps-skills 的源码或 node_modules 提交进咱们仓库**（它是外部依赖，几百个文件）。
  在 `.gitignore` 里排除它，仓库里只留适配层 + 安装脚本。

### 2) 环境 —— 写成"从零复现步骤"（因为没法打包）

新建 `tools/wps_spike/README.md`，必须包含：

| 项 | 要写什么 |
|---|---|
| 我的环境 | Windows 版本 / WPS 版本号 / Node 版本 / wps-skills 的 commit（在它目录里跑 `git rev-parse HEAD`） |
| 从零步骤 | 每条命令原样贴：克隆 → `npm install` → `npm run build` → 加载项安装脚本 → 启动命令 → 我调的哪个工具、传了什么参数、返回什么原文 |
| 踩过的坑 | 遇到什么问题、怎么解决的（**这部分最值钱，别省**） |
| 一句话风险 | 换台机器复现最容易卡在哪里 |

### 3) 证据 —— 证明"真跑通了"，不是"我觉得能跑"

- MCP server 启动日志（贴原文，别改写）
- WPS 里真的出现脚本写入内容的**截图**（带时间）
- 不允许出现"应该可以 / 大概能跑"

### 自查（交付前自己先过一遍）

> 如果你把自己的机器格式化了，还能照着这份 README 再搭起来吗？不能，就说明没写全。

## 二、我（George）的验收动作（三个都不能省）

1. **看 PR**：改动的文件是不是**只有适配层**？（有没有顺手改 `src/`、`tests/`、`static/`？有没有把第三方代码塞进来？）
2. **在自己的机器上照 README 从零走一遍**：走得通 = 真交付；走不通 = 你补步骤。
   （这一步不能跳，否则合并的是"你说你能跑"，不是"它真的能跑"。）
3. **确认版本锁**：README 里有没有 wps-skills 的 commit 号？以后上游改了接口，我们得知道当初锁的是哪一版。

## 五、附：万能交接模板（以后别的任务也能套）

```
1) 目标：这次做的是什么，做到什么程度算完（不做什么也要写清）

```
